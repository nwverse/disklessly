# F-B1 decisions

The restore design in `docs/design.md` §§5.6.4b and 5.8 leaves a few choices open. These are the choices this implementation makes. The pure decision function is `RestoreRecovery.decide`; the runner is `RestoreCoordinator`.

1. **`ownerAlive` means a different live process.** The process that currently holds the journal passes `false` and is allowed to act. A live foreign owner is `noopLiveOwner` with no rename, delete, or mirror write, including when the layout is ambiguous. A missing journal is not covered by that no-op: a stale `state.restored` mirror is retired only when the destination is the stub and staging is gone, and is otherwise rejected.

2. **Early phases accept an undone layout.** `prepared`, `extracted`, and `stubParked` treat "stub still at the destination and staging absent or empty" as a valid pre-effect, so rollback is idempotent. `installed` does too. `active` and later do not: losing the restored bundle there is a reject, not a silent rollback.

3. **cdhash.** On macOS, `codesign -dvvv` `CDHash` (lowercased) wins when it succeeds. Unsigned bundles and Linux use the sha256 of `Contents/MacOS/<CFBundleExecutable>`. Tree hash is sha256 over sorted relative paths, type, mode, symlink target, and file bytes. Extraction markers live in the staging directory, never inside the bundle.

4. **Clean twice.** The default probe interval is 5 seconds (`DISKLESSLY_PROBE_INTERVAL`, and `RestoreCoordinator.probeIntervalOverride` in tests). `0` is allowed. The streak is in memory and resets when the phase changes or the probe is not clean. Destination renames (`moveAppAside`, `restoreStub`, `regenerateStub`) and `deleteIdenticalCopy` require a clean probe and a streak of at least 2. Rolling back `prepared` / `extracted` / `stubParked`, and the pre-effect of `installed`, does not. `installed` plus a clean streak is a restore-out whose outcome is `rolledBack`, and it skips the detach delay. A normal quit from `active` waits `DISKLESSLY_DETACH_DELAY` unless `pendingOutcome` is already `rolledBack`.

5. **Faults live in `stateDir/config.json`.** `faults` is a list of `"<phase>:<beforeJournal|afterJournal|afterMutation>"`. `faultMode` is `kill` (SIGKILL) or `raised` / `throw` (`InjectedFault`). The keys are read only when present, so an in-process test fault is not cleared by a config that never mentioned faults. `gc` and `launch` must not run while a kill fault is still configured.

6. **`active` does not move a bundle.** Its mutation is the `state.restored` mirror. The mirror may lag the journal; recovery trusts the journal and rewrites the mirror after it claims a dead owner.

7. **Replacements are watched.** Same bundle id and a different inode or cdhash at the controlled destination is not a reject and is not deleted merely because the bundle id matches. Deletion requires an unchanged inspection (cdhash, tree hash, and bundle id) plus a verified archive (cache `images/<imageId>.dmg` or the repo image, sha256). Otherwise the bundle is retained under `stateDir/retained/<appId>/<txid>-<name>.app` and launch fails with `EX_RESOLUTION` (14) until `resolve`.

8. **Stub identity is the bundle id `*.256stub`, not the inode.** Regeneration allocates a new inode. Recovery will rebuild a stub only onto an empty destination, from the journal plus `locateLauncher` (or a tiny shell launcher if that lookup fails), and `codesign --sign -` on macOS. It never overwrites a non-empty destination. A missing parked stub at `appMoved` / `stubBack` is regenerable; a foreign bundle in that role is a reject.

9. **Ambiguous layouts are frozen.** Symlinks, path escapes, duplicate roles, and unexpected staging names produce `reject` and a `doctor` repair string. Nothing is deleted. The repair is to move the unexpected items out of staging and run `disklessly gc`.

10. **`launch` follows `manifest.mode`. `restore` forces restore mode** on a copy of the manifest. `--permanent` is not part of this slice; `LaunchArguments` reports it as an unknown option (`EX_USAGE`).

11. **Hooks** are `stateDir/hooks/<bundleId>/{pre-launch,post-quit}` and the matching `.d` directories. A non-zero pre-launch sets `pendingOutcome=rolledBack`, runs restore-out, and returns `EX_HOOK` (10). Post-quit runs once per epoch, and only after a successful open (`didLaunch`). A pre-launch failure therefore does not run post-quit. If the bundle changed and the pending outcome is `rolledBack`, the stored outcome stays `rolledBack` and `needsResolution` is still set.

12. **Retirement is one `state.json` write** (`applyRetirement`): drop `restored[appId]`, set `lastOutcome` `{name, at, txid}`, set `needsResolution` or clear it, and update `lastUsed` only when the outcome is not `rolledBack`. The outcome and timestamp are stored on the journal before that write. Replay uses those values and does not invent a later time. `retired` is journaled, the state write is fsynced, `closed` is journaled, then staging (unless the retained path is inside it) and the journal are removed.

13. **The disk image is detached during `extracted`, before `stubParked`.** `mountPath` is saved on the journal before attach, so a crash during attach still has a path to detach. Restore recovery never reads `state.mounts` and never asks for an attachment list.

14. **`gc` finishes a clean recovery in-process.** Only `busy`, `unknown`, `held`, and `delay` are handed to a detached `disklessly hook watch --app <id>`. The watcher is spawned with `posix_spawn` and `POSIX_SPAWN_SETSID` (glibc `0x80`, Darwin `0x0400`) so it does not depend on python3. A second caller that sees that live owner returns without mutating.

15. **File URLs are decoded once.** `StubArgv` uses `URL.path` and does not call `removingPercentEncoding`. `file:///w/a%2520b.txt` is `/w/a%20b.txt`. `file:///y%20z.txt` stays `/y z.txt`.

16. **`--` ends Launch Services noise filtering.** Before the separator, `-psn_*`, `-NS*`, and `-Apple*` are dropped. After it, `-NSnotes.txt` is a document. An invalid `DISKLESSLY_STUB_BINARY` is `EX_USAGE` and does not fall back to a sibling. A resolved launcher whose real path is the CLI is `EX_FAILURE`.

17. **`resolve --keep-updated` repacks on macOS only.** Linux returns `EX_UNSUPPORTED` and does not clear the resolution record. `--discard` and `--export` work on both. An invalid code signature is `EX_INTEGRITY` and is not discarded by the keep-updated path. A cdhash change without `--trust` is `EX_USAGE`.

18. **`find` prefers the pinned image.** `manifest(named:)` uses an explicit image id, then `state.apps[id].imageId`, then the bundle id or display name. `doctor --fix` runs `gc` and then reports. `doctor` is not a generic success: open journals with rejected layouts, stale mirrors, and `needsResolution` are issues.

19. **A crash at `active` before `open` still finishes as `restoredOut`** when the bundle is unchanged, because forward completed. `rolledBack` is reserved for the installed-phase clean path, an explicit pre-launch rollback, and a changed bundle whose pending outcome was already `rolledBack`. `lastUsed` moves only for outcomes other than `rolledBack`.

20. **The placeholder unit assertion was replaced.** `testRestoreModeIsExplicitlyRefusedUntilRecoveryExists` required the string "restore mode is disabled until durable restore recovery is implemented". That refusal was the stand-in until this recovery existed. The replacement, `testRestoreModeRunsJournalDetachesBeforeActiveAndSkipsMountRecovery`, requires the journaled transaction, detach-before-active, and no mount session. On Linux, mount-mode launch still throws exactly "launch requires macOS hdiutil and Launch Services". On macOS the same call reaches attach of the fixture bytes and must fail as `diskImage` recording the selected attach command. When the probe selects hdiutil, that record includes `(exit 1)`. When it selects diskutil, the record includes a non-zero `(exit N)`. No journal or mount session is written. The tool's own sentence is not part of the assertion. No other existing assertion was removed or weakened.

21. **The in-use probe ignores our own launcher.** `ps` matches the destination path in both `/var/...` and `/private/var/...` spellings. A command counts only when it is not an ancestor of the caller and its executable basename is not `disklessly`, `disklessly-stub`, or `open`. The stub that is performing the launch lives at `<dest>/Contents/MacOS/disklessly-stub`, so its argv contains the destination; that is not a foreign user. `open` / `open -n -a <dest>` keeps the destination in its arguments for the whole Launch Services handshake and is the launcher, not a user of the bundle. The restored app and helpers such as `tail -f <dest>/Contents/Info.plist` still count as busy.

22. **The manifest hash is the restored tree, not the pre-image staged app.** `pack` attaches the ULMO it just created and `ditto`s the app out with the same command restore uses, then records that copy's cdhash and tree hash. `hdiutil create -srcfolder` can change modes and, on macOS 26 and later, store `com.apple.provenance` as AppleDouble `._*` files whose bytes differ on every copy. Those sidecars (and `__MACOSX`) are removed from the extracted tree before it is hashed or installed; every other path, mode, symlink, and file byte still has to match. On macOS, writing `Contents/._Info.plist` can land as an AppleDouble/xattr that `contentsOfDirectory` does not list, so the tree hash does not change and there is nothing for the sweep to delete. `subpathsOfDirectory` may still print that name; the unit test checks the hasher's `contentsOfDirectory` listing, requires deletion and a restored hash only when that walk can see the sidecar, and always requires that an ordinary extra file changes the hash and survives the sweep. The tree walk lists directories directly so a `.app` package root is not skipped, and relative paths treat `/var` and `/private/var` (also `/tmp` and `/etc`) as the same location. cdhash is `codesign -dvvv`'s `CDHash` of the main Mach-O, including when the staged directory is not named `.app` (`codesign` rejects `app.new` as a bundle) and when `codesign` prints the hash with a non-zero status. `codesign --force --sign -` during pack is the stub install, not a re-sign of the image. A failed extraction detaches the image it attached, deletes the unverified `app.new`, and retires the journal as `rolledBack` before the error is returned. A failed detach is not recorded as detached, so recovery tries again.

23. **A restore-mode update is a new Mach-O, not trailing bytes.** The A34d fixture used to append `updated\n` to `Contents/MacOS/Restore` and run `codesign --force --sign -`. That file is no longer a Mach-O. macOS 27 rejects it with "main executable failed strict validation" after "replacing existing signature". The update is a second `swiftc` binary that references a different build tag, copied over the executable and signed with the same ad-hoc command, then checked with `codesign --verify --strict`. Its CDHash must differ from the running v1 bundle.

24. **Tool sentences are not a classifier.** `hdiutil`, `diskutil`, and `codesign` may be spawned with `LC_ALL=C` and `LANG=en_US.UTF-8`. On macOS 27 that does not change hdiutil's language: it follows AppleLanguages, so `LC_ALL=C`, `LANG=en_US.UTF-8`, `-AppleLanguages '(en)'`, and `-plist` still print `无法识别映像` for an unrecognized image and exit 1. Attach, detach, and `codesign --verify` succeed or fail by exit status and, for attach, by whether the plist lists the mount point. The stderr text is stored on a non-zero exit and is not matched. `codesign -dvvv` contributes only the `CDHash=` field; that key stayed stable on a zh-Hans Mac, and codesign has no `-plist` form of it. `open` does not get the locale override, because the launched app inherits it.

25. **Attach and detach prefer `diskutil image`.** `diskutil image --help` exiting 0 selects `diskutil image attach --plist --readOnly --mountOptions nobrowse --mountPoint`. There is no `--noautoopen` on that command. Detach is `diskutil eject`; a forced detach uses `diskutil eject force` and, if that exits non-zero, `diskutil unmount force`. Any other help status keeps `hdiutil attach -plist -readonly -nobrowse -noautoopen -mountpoint` and `hdiutil detach` (`-force` when forced). `hdiutil create -format ULMO` still builds pack images. `diskutil image create from` can write ULMO, but it scrubs and treats unreadable ownership differently, so it is not the pack path.

26. **The post-quit watcher is a separate session.** Production `RestoreServices.live` sets `detachWatcher`. After `didLaunch`, `launch` spawns `disklessly --state-dir … hook watch --app …` with `POSIX_SPAWN_SETSID` only (Darwin `0x0400`, glibc `0x80`) and records that pid as the journal owner. `setsid` also creates the new process group. `POSIX_SPAWN_SETPGROUP` is not combined with it: on glibc the child is already a group leader when `setsid` runs, and `setsid` then returns `EPERM`. `--no-wait` returns after the handoff. The default wait polls until the journal is gone and adopts only when that owner is dead, so a second watcher is not started while the first is alive. The stub starts `disklessly launch` the same way and `waitpid`s it, so Launch Services tearing down the stub's process group does not deliver the SIGKILL (exit 137) that used to kill an in-process watch. `open` is given 30 seconds; a still-running `open` is not a bundle user (decision 21). The app lock is opened `O_CLOEXEC`, because an inherited `flock` is on the open file description and the child then blocks on its own lock. `launch`, `hook`, and `restore` ignore `SIGHUP`. Watcher stdout and stderr go to `stateDir/logs/hook-watch.log`. Tests leave `detachWatcher` false and recover in-process.

27. **The engine the stub execs is `<stateDir>/bin/disklessly`.** `init`, `pack`, `launch`, and `install-engine` copy the running `disklessly` there and write `disklessly.stamp` with `version` and `revision` (revision 2 is the streaming-hash CLI; a missing stamp is older). Stub resolution is `DISKLESSLY_CLI`, then that stable path, then `stub.json`'s `disklesslyPath`, then `PATH`. `stub refresh --app ID` rewrites `disklesslyPath`, `engineVersion`, and `engineRevision` and re-signs on macOS. `doctor`'s `engine` check warns, and does not fail the command, when the stable binary is missing or older, and when it is missing also warns about stubs that still name another missing or older binary.

28. **Commands load `<stateDir>/config.json`.** `--config` / `DISKLESSLY_CONFIG` replaces that file. Otherwise the stored `backend` is what `status` reports, and explicit `DISKLESSLY_*` path overrides win, including `--state-dir` even when this process's `ProcessInfo.environment` does not yet show the `setenv`. `init --backend icloud` therefore stays `icloud`. With no stored config, `backend` stays `local` even when the default repository path is in iCloud Drive. `openBackend` still selects `ICloudFolderBackend` when the path looks like iCloud, independent of the `backend` field.

29. **`open` is bounded and is not a user of the bundle.** See decision 21. A Launch Services `open` that never returns used to sit in front of `markLaunched` and the post-quit loop while the journal stayed `active`. The 30 second bound is on the detached `open` only; the restored app is not killed when that bound elapses.
